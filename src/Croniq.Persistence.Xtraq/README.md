# Croniq.Persistence.Xtraq

This project wires the Croniq persistence abstractions to the Xtraq-generated SQL layer (stored procedures + TVPs). Key guardrails:

- Only stored procedures generated by Xtraq may be called. Do **not** add ad-hoc SQL or inline queries (e.g. no direct `SELECT` for IDs).
- Keys are string-based for UX (`JobKey`, `TriggerKey`) but persisted with numeric IDs; Procs resolve/maintain these mappings.
- Actor/audit data must be provided via `XtraqOptions.Actor`.
- Generated files under `Xtraq/*` are read-only; rerun `xtraq snapshot`/`xtraq build` after SQL changes.
