## Prioritized gaps

Severity rubric for fix order:
- **High** — touches auth, persistence, scheduler correctness, or external contracts
- **Medium** — business logic without external surface
- **Low** — UI-only or documentation-adjacent

### High

1. **MCP `mcp:read` enforcement** — `crates/croniq-server/tests/integration.rs`
   - `mcp_post_without_mcp_read_returns_403`: send a `tools/list` POST with
     a token that has `mcp:write` only → assert 403.
   - `mcp_post_with_admin_passes`: same call with `admin` scope → assert 200
     and a JSON-RPC body.

2. **MCP `mcp:write` enforcement on mutation tools** — same file
   - `mcp_call_update_job_without_mcp_write_returns_403`: token with
     `mcp:read` only → 403 when `params.name == "update_job"`.
   - `mcp_call_list_jobs_with_mcp_read_passes`: token with `mcp:read` only →
     non-mutation tool succeeds.

3. **`PUT /v1/jobs/{key}` round-trip** — `crates/croniq-server/src/api/jobs.rs`
   - `update_job_patches_description`: PUT `{"description": "x"}` → next
     GET returns the new description, other fields unchanged.
   - `update_job_explicit_null_clears_timeout`: PUT `{"timeout": null}` →
     row's `timeout` column is `NULL`.
   - `update_job_dsl_managed_returns_409`: PUT against a Croniqfile-managed
     key → `JobError::DslManaged`.

4. **`PUT /v1/calendars/{id}` validation** — new module test in
   `crates/croniq-server/src/api/calendars.rs`
   - `update_calendar_invalid_dsl_returns_422`: PUT with malformed rule
     line → 422 with parser error fields.
   - `update_calendar_persists`: round-trip a name change.

5. **`PUT /v1/api-clients/{id}` scope rules** — new module test in
   `crates/croniq-server/src/api/auth_endpoints.rs`
   - `update_api_client_empty_scopes_rejected`: PUT `{"scopes": []}` → 400.
   - `update_api_client_deactivate_persists`: PUT `{"is_active": false}` →
     subsequent token from this client is rejected by auth.

6. **Forecast bucketing equivalence** — `crates/croniq-scheduler/src/forecast.rs`
   - `forecast_buckets_three_fires_across_two_buckets`: build 3 triggers
     firing at +5m, +12m, +18m with `bucket=10m, window=60m` → assert
     bucket-0 has 1 job, bucket-1 has 2.
   - `forecast_clamps_window_to_240`: request `window_minutes=500` →
     assert returned `window_minutes` is 240.
   - `forecast_dedups_jobs_per_bucket`: same trigger fires twice in one
     bucket → `bucket.jobs.len() == 1`.

### Medium

7. **Croniqfile `mcp { }` parser/compile** — `crates/croniq-config`
   - `parser::parse_mcp_block_minimal`: parse `mcp {}` → AST has one
     `Item::Mcp` with empty directives.
   - `compile::mcp_default_enabled_when_absent`: compile a Croniqfile with
     no `mcp { }` block → `runtime.mcp` is `None` (the `is_none_or`
     fallback in `main.rs` then defaults to enabled).
   - `compile::mcp_unknown_value_currently_disables`: compile
     `mcp { enabled garbage }` → `runtime.mcp.unwrap().enabled == false`.
     This is the silent-disable behavior from review item #1; once the
     parser is hardened to reject the value, this test flips to
     "expects parse error".

8. **MCP CRUD tools — at least one happy-path test per resource** —
   `crates/croniq-mcp/src/tools.rs`
   - `create_then_update_then_delete_job`: smoke-tests three of the new
     tools end-to-end via an in-memory store fixture.
   - `create_then_delete_calendar`: same for calendars.
   - `create_then_delete_schedule`: same for schedules.
   - `list_dead_letters_returns_state_field`: assert the response payload
     shape is stable (insta snapshot recommended).

9. **`MUTATION_TOOL_NAMES` ↔ `#[tool]` parity check** —
   `crates/croniq-mcp/src/tools.rs` (test mod)
   - `mutation_tool_names_matches_registered_mutations`: parse
     `tool_router!()`'s registered list at test time and assert
     `MUTATION_TOOL_NAMES` ⊇ every fn flagged as mutation. Catches the
     drift risk from review item #3.

### Low

10. **`EditJobDialog` seeds initial values** — requires Vitest setup
    first.
11. **`CalendarPicker` renders all calendars + the (none) option** —
    same.
12. **UI hooks `useUpdateJob` etc. send the right body** — same.

## Test infrastructure recommendations

1. **MCP integration harness** (priority: high). Extend
   `crates/croniq-server/tests/integration.rs` with a `mcp_post(token,
   body)` helper that signs a JWT, hits `/mcp`, and returns the response.
   Roughly 80–100 LOC of fixture, then the High-severity tests above are
   ~10 lines each.
2. **UI test setup** (priority: medium). Add Vitest + React Testing
   Library to `ui/`. The dashboard has grown enough that bare TypeScript
   typechecks no longer cover the dialogs and form-state interactions.
3. **Snapshot tests for MCP tool responses** (priority: medium). Use
   `insta` in `croniq-mcp/src/tools.rs` to lock the JSON response shape
   for each tool. Catches schema drift that today only shows up when an
   AI client breaks.
4. **CHANGELOG-non-empty CI gate** (priority: low). Reject PRs that
   touch `crates/` without adding to `[Unreleased]`. Mechanically
   prevents the "tag with empty changelog" slip that motivated this
   write-up.
5. **Coverage baseline via `cargo tarpaulin`** (priority: low). Useful
   once the MCP harness lands so we can see which tools' response
   branches stay uncovered.
